## DeepSeek Harness: рабочий процесс "Issue → PR → Code Review → Merge"

DeepSeek Harness (`dsh`) — это открытый агентный фреймворк от DeepSeek AI, построенный на архитектуре **«всё — плагин»**. Ниже представлен детальный план, как с его помощью автоматизировать цикл разработки от Issue до Merge.

---

### 1. Подготовка окружения

Перед началом работы установите DeepSeek Harness.

**Способ 1 — быстрый запуск через npx (рекомендуется для начала)**:
```bash
npx @deepseek-ai/dsh web
```
Команда запустит Web-интерфейс по адресу `http://127.0.0.1:3080`.

**Способ 2 — запуск из исходников** (если нужна полная кастомизация):
```bash
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
```


Для работы с GitHub-репозиторием вам также понадобится:
- Установленный `git` и настроенный доступ к вашему репозиторию.
- GitHub Personal Access Token (для автоматизации операций через API).

---

### 2. Создание Issue на GitHub

В вашем проекте на GitHub создайте Issue с описанием задачи, которую должен решить агент. Чем детальнее будет описание, тем точнее Harness сможет сгенерировать код.

**Рекомендации по заполнению Issue:**
- Чётко сформулируйте **цель** (что должен делать код).
- Укажите **требования** (язык, библиотеки, API).
- Приложите примеры входных/выходных данных.
- Опишите критерии приемки (как проверить, что задача решена).

---

### 3. Настройка DeepSeek Harness для работы с Issue

DeepSeek Harness из коробки **не имеет встроенного интеграционного сценария** «прочитай Issue → напиши PR». Однако его архитектура «всё — плагин» позволяет **написать собственный плагин или использовать существующие инструменты** для реализации этого рабочего процесса.

**Вариант А — использование существующих команд (если они есть в вашей версии):**

В некоторых источниках упоминаются утилиты, например:
- `dsh-code-review` — для проверки Pull Request'ов.
- `dsh-find-simplifications` — для поиска упрощений в коде.

Проверьте доступные команды в вашей установке:
```bash
pnpm dsh --help
```
или (если установлен глобально):
```bash
dsh --help
```

**Вариант Б — написание собственного плагина (рекомендуемый подход):**

DeepSeek Harness позволяет создавать плагины, которые экспортируют функцию `apply` и регистрируют новые возможности через контекст `ctx`.

**Архитектура плагина для автоматизации Issue→PR:**

1. Плагин подключается к GitHub API (через токен).
2. Получает содержимое Issue по его номеру или URL.
3. Передаёт описание задачи в агент Harness (например, через `dsh-agent-loop`).
4. Агент генерирует код, создаёт новую ветку, коммитит изменения и открывает Pull Request.

**Пример структуры плагина (TypeScript):**
```typescript
import type { Context } from '@deepseek-ai/cordis'

export function apply(ctx: Context) {
  ctx.command('gh.issue-to-pr <issueUrl>', 'Convert GitHub issue to PR')
    .action(async (_, issueUrl) => {
      // 1. Получить содержимое Issue через GitHub API
      // 2. Передать задачу в агент Harness
      // 3. Сгенерировать код
      // 4. Создать PR через GitHub API
    })
}
```


Более подробные инструкции по разработке плагинов доступны в [документации](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/index.zh.md).

---

### 4. Запуск агента и генерация кода

После того как плагин или скрипт получил описание задачи из Issue, он передаёт её в агентский цикл Harness.

**Запуск агента вручную (для отладки):**
```bash
pnpm dsh agent "опишите задачу здесь"
```

Агент DeepSeek Harness может:
- Анализировать код вашего репозитория.
- Генерировать новый код или изменения.
- Создавать коммиты и пушить их в новую ветку.

**Важный нюанс:** DeepSeek Harness находится на стадии **developer preview** и активно развивается — возможны breaking changes.

---

### 5. Создание Pull Request

После того как код сгенерирован и запушен в ветку, необходимо открыть Pull Request.

**Способы:**
1. **Через плагин** — ваш плагин может использовать GitHub API для автоматического создания PR (как показано выше).
2. **Вручную** — после пуша ветки вы открываете PR на GitHub в обычном порядке.

**Важно:** официальный репозиторий DeepSeek Harness **не принимает внешние PR** на данном этапе. Но это ограничение **не относится к вашим собственным проектам** — вы можете использовать Harness для автоматизации работы в любом репозитории, где у вас есть права на запись.

---

### 6. Code Review и Merge

После создания PR вы (или ваша команда) проводите Code Review.

**Автоматизированная проверка PR:**
В DeepSeek Harness есть встроенный навык `dsh-code-review`, который помогает проверять PR на соответствие стандартам репозитория (соглашения из `AGENTS.md`, defensive-паттерны, качество кода).

Чтобы использовать его:
```bash
pnpm dsh code-review <номер-PR>
```
или через Web UI.

**После успешного ревью:**
- Выполняете merge (через GitHub UI или командой `git merge`).
- Удаляете временную ветку (опционально).

---

### 7. Полный цикл (схема)

```
1. Создаёте Issue в вашем GitHub-репозитории.
2. Запускаете DeepSeek Harness с плагином, который:
   a) Читает Issue через GitHub API.
   b) Передаёт описание задачи агенту.
   c) Агент генерирует код и создаёт ветку с изменениями.
   d) Плагин открывает Pull Request.
3. Проводите Code Review (вручную или с помощью dsh-code-review).
4. Выполняете Merge → получаете рабочий код.
```

### Важное замечание

DeepSeek Harness — это **агентный фреймворк**, а не готовое «коробочное» решение для автоматического Issue→PR. Для реализации описанного цикла вам потребуется:
1. Написать плагин (или адаптировать существующий).
2. Настроить интеграцию с GitHub API.
3. Обеспечить безопасное хранение токенов доступа.

Однако благодаря архитектуре «всё — плагин» и открытому исходному коду (лицензия MIT) вы можете построить именно тот рабочий процесс, который нужен вашему проекту.

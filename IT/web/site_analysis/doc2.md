## 1.1 Google Fonts

## В чём проблема с Google Fonts

Когда вы подключаете шриты через Google Fonts, в HTML-коде сайта стоит примерно такая строка:

```html
<link href="https://fonts.googleapis.com/css2?family=Roboto:wght@400;700&display=swap" rel="stylesheet">
```

При каждой загрузке страницы браузер посетителя делает запрос к серверу `fonts.googleapis.com` (или `fonts.gstatic.com`), чтобы скачать файл шрифта. Вместе с этим запросом **автоматически передаётся IP-адрес посетителя** — технически это неотъемлемая часть протокола HTTP, отключить её нельзя. [```scanbase.ru```](https://scanbase.ru/google-analytics-fonts-152-fz-onlayn-shkoly/)

IP-адрес — это персональные данные по [ст. 3 ФЗ-152](https://www.kontur-extern.ru/info/normativ/document/1/507366-federalnyy-zakon-ot-27-07-2006-n-152-fz), потому что по нему можно идентифицировать конкретное устройство и, косвенно, человека. [```metrikus.ru```](https://metrikus.ru/)

Серверы Google Fonts находятся за рубежом (США, Ирландия). Значит, при каждом визите любого пользователя — даже если он просто открыл главную страницу и сразу закрыл — его IP-адрес улетает за границу. Это **трансграничная передача персональных данных**. [```сайтвпорядке.рф```](https://xn--80aegeri0ahken4n.xn--p1ai/blog/zarubezhnye-servisy-na-sajte-riski)

## Почему это легко пропустить

В отличие от Яндекс.Метрики или формы записи, Google Fonts **не виден пользователю**. На странице нет баннера, нет чекбокса, нет виджета — просто текст отображается красивым шрифтом. Владелец сайта часто не знает, что шрифты грузятся с серверов Google, потому что:

- Шрифт был встроен в WordPress-тему «из коробки»
- Вебмастер подключил шрифт при вёрстке и забыл
- Конструктор (Elementor) автоматически подтянул Google Fonts для выбранного типографического пресета

По оценкам аналитиков, около 30% российских сайтов используют Google Fonts и даже не подозревают о трансграничной передаче. [```scanbase.ru```](https://scanbase.ru/google-analytics-fonts-152-fz-onlayn-shkoly/)

## Как исправить

Решение одно: **разместить шрифты локально на своём сервере**. Тогда запрос идёт к вашему домену, IP никуда не передаётся, трансграничной передачи нет. [```scanbase.ru```](https://scanbase.ru/google-analytics-fonts-152-fz-onlayn-shkoly/)

### Пошаговая инструкция

**Шаг 1. Скачать шрифт**

Зайдите на [Google Fonts](https://fonts.google.com/), найдите нужный шрифт (например, Roboto), скачайте файлы в форматах `.woff2` и `.woff`. Или используйте сервис [google-webfonts-helper](https://gwfh.mranftl.com) — он сразу генерирует CSS и архив с файлами.

**Шаг 2. Загрузить файлы на сервер**

Для WordPress: загрузите файлы шрифтов в папку темы, например:
```
/wp-content/themes/ваша-тема/fonts/roboto-regular.woff2
/wp-content/themes/ваша-тема/fonts/roboto-bold.woff2
```

**Шаг 3. Подключить в CSS**

Вместо:
```html
<link href="https://fonts.googleapis.com/css2?family=Roboto:wght@400;700&display=swap" rel="stylesheet">
```

Добавить в `style.css`:
```css
@font-face {
  font-family: 'Roboto';
  font-style: normal;
  font-weight: 400;
  font-display: swap;
  src: url('/wp-content/themes/ваша-тема/fonts/roboto-regular.woff2') format('woff2');
}

@font-face {
  font-family: 'Roboto';
  font-style: normal;
  font-weight: 700;
  font-display: swap;
  src: url('/wp-content/themes/ваша-тема/fonts/roboto-bold.woff2') format('woff2');
}
```

**Шаг 4. Удалить ссылку на Google Fonts**

Найти и убрать из HTML (или из настроек темы / Elementor) строку подключения `fonts.googleapis.com`.

**Шаг 5. Проверить результат**

F12 → Network → фильтр `font` → перезагрузить → все запросы к шрифтам должны идти к вашему домену (`doctorsviridov.ru`), а не к `fonts.gstatic.com`.

Если сайт на WordPress, чаще всего Google Fonts подключается одним из трёх способов:

| Где подключается | Как убрать |

## То же самое касается других сторонних ресурсов

Принцип один: **любой запрос к зарубежному серверу передаёт IP-адрес посетителя за рубеж**. Google Fonts — не единственный случай:

| Ресурс | Что передаётся за рубеж | Как исправить |
|---|---|---|
| **Google Fonts** | IP при загрузке шрифта | Скачать и разместить локально [```scanbase.ru```](https://scanbase.ru/google-analytics-fonts-152-fz-onlayn-shkoly/) |
| **Google reCAPTCHA** | IP + отпечаток устройства | Заменить на Яндекс SmartCaptcha [```сайтвпорядке.рф```](https://xn--80aegeri0ahken4n.xn--p1ai/blog/zarubezhnye-servisy-na-sajte-riski) |
| **YouTube embed** (`<iframe>`) | IP при загрузке плеера | Заменить на скриншот-ссылку или загрузить на RuTube / VK Видео [```сайтвпорядке.рф```](https://xn--80aegeri0ahken4n.xn--p1ai/blog/zarubezhnye-servisy-na-sajte-riski) |
| **Google Maps** | IP при загрузке карты | Заменить на Яндекс Карты или 2GIS |
| **Vimeo embed** | IP при загрузке плеера | То же, что YouTube |
| **Пиксели соцсетей** (Meta, VK) | IP + cookie | Убрать или получить согласие |

Если на сайте doctorsviridov.ru убрать Google Fonts и заменить YouTube-вставки (если они есть) на скриншоты-ссылки — трансграничная передача ПДн через сторонние ресурсы будет полностью устранена.

## 1.2

"заменить YouTube-вставки (если они есть) на скриншоты-ссылки —" - но http ссылка все равно будет?

Да, ссылка останется — но **тип передачи данных и юридический риск кардинально меняются**.

## В чём разница: iframe YouTube vs ссылка-скриншот

### Вариант 1: `<iframe src="https://www.youtube.com/embed/...">` (сейчас)

Когда браузер загружает такой iframe:

1. Браузер делает запрос к `youtube.com` → **IP-адрес посетителя уходит на сервер Google (за рубеж)**.
2. YouTube может ставить cookie, собирать отпечаток устройства, фиксировать факт просмотра.
3. Это **трансграничная передача ПДн** (IP + поведенческие данные) в автоматическом режиме, без согласия пользователя.

---

### Вариант 2: Ссылка-скриншот (картинка + `href`)

```html
<a href="https://www.youtube.com/watch?v=XYZ" target="_blank">
  <img src="/wp-content/uploads/2024/10/preview-video-1.jpg" alt="Смотреть видео на YouTube">
</a>
```

Что происходит при загрузке страницы:

- Браузер запрашивает только картинку (`preview-video-1.jpg`) с **вашего сервера** → IP никуда не улетает.
- Ссылка (`href`) просто хранится в HTML. Она **не инициирует запрос к YouTube**, пока пользователь не кликнет.
- В момент клика браузер открывает YouTube в новой вкладке — и тогда IP уйдёт на YouTube, но это уже **действие самого пользователя**, а не автоматическая передача со стороны вашего сайта.

**Юридически это не считается трансграничной передачей ПДн со стороны оператора сайта.** Оператор не собирает и не передаёт данные за рубеж — он лишь разместил ссылку.

---

## Важные нюансы, чтобы не потерять в безопасности и UX

1. **Картинка должна быть у вас на сервере.**  
   Если вы оставите `src="https://i.ytimg.com/..."` (превью от YouTube), то при загрузке страницы IP снова уйдёт на Google. Поэтому: скачайте превью-кадр с YouTube и положите его в папку сайта (например, `/uploads/`).

2. **Ссылка может вести на YouTube.** Это нормально: вы не обязаны хостить видео у себя, достаточно убрать автоматическую загрузку чужого контента на странице.

3. **Добавьте атрибут `target="_blank"`.** Тогда видео откроется в новой вкладке, и пользователь не уйдёт с вашего сайта.

4. **Добавьте `rel="noopener noreferrer"`** к ссылке — это хорошая практика безопасности:
   ```html
   <a href="https://www.youtube.com/watch?v=XYZ" 
      target="_blank" 
      rel="noopener noreferrer">
     <img src="/wp-content/uploads/preview.jpg" alt="Видеоотзыв пациента">
   </a>
   ```

## Если хочется совсем без внешних ссылок

Альтернативы, где вообще нет внешних HTTP-запросов:

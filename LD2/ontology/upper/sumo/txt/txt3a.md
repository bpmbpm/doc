## 1
Покажи нашу аналогию также на visio: мы из боковой панели с шаблонами (как она называется) перетаскиваем примитив, например, квадрат и на рабочем листе (canvas?) появляется элемент с id состоящим из названия master фигуры с добавлением через точку порядкового номера. При добавлении например второго такого же элемента на тот же лист получим master55.2. 


Для Алисы лучше взять проверяемый SUMO-атрибут **`Female`**:

```lisp
(attribute Alice01 Female)
```

Он означает: **`Alice01` обладает атрибутом `Female`**, то есть является женщиной/женского пола. Именно такая конструкция — `(attribute ?X Female)` — приводится как пример использования предиката `attribute` в SUMO. [arxiv](https://arxiv.org/html/1705.10217v3)

## Простая запись для рассказа

```lisp
;; 1. На границе создаётся и маркируется физический индивид
(instance Alice01 Human)

;; 2. В карточку Alice01 вписывается имя
(names "Алиса" Alice01)

;; 3. В карточку Alice01 вписывается атрибут
(attribute Alice01 Female)

;; 4. Создаётся второй физический индивид — автомобиль
(instance AliceCar01 Automobile)

;; 5. Фиксируется отношение владения
(possesses Alice01 AliceCar01)

;; 6. В карточку автомобиля вписывается абстрактное значение цвета
(attribute AliceCar01 Red)
```

Здесь:

- `Alice01` и `AliceCar01` — физические индивиды, получившие `id`;
- `"Алиса"`, `Female`, `Red` — абстрактные значения, которые **не получают новых физических `id`**, а привязываются к уже существующим индивидам;
- `names` — отношение «строка является именем сущности»;
- `attribute` — отношение «индивид обладает значением атрибута».

## Иерархии

### `Alice01`

```text
Entity
└── Physical
    └── Object
        ├── ... → Organism → Hominid → Human → Alice01
        └── ... → Agent → CognitiveAgent → Human → Alice01
```

`Alice01` — физический индивид класса `Human`; `Human` имеет двух родителей, и обе ветви ведут к `Physical`.

### `Female`

```text
Entity
└── Abstract
    └── Attribute
        └── SexAttribute
            └── Female
```

`Female` — значение атрибута из абстрактной ветви. Оно не является отдельной женщиной и не имеет собственного места в пространстве-времени; это качество, приписываемое физическому индивиду.

### `Red`

```text
Entity
└── Abstract
    └── Attribute
        └── ColorAttribute
            └── Red
```

`Red` — абстрактное значение цвета, которое приписывается `AliceCar01`.

### `names`

```text
Entity
└── Abstract
    └── Relation
        └── Predicate
            └── BinaryRelation
                └── names
```

`names` — не атрибут, а бинарное отношение:

```text
"Алиса" ── names ──> Alice01
```

Оно связывает строку-имя с индивидом.

## Аналогия с Visio

Ваша аналогия очень точная. В Visio боковая панель с шаблонами называется **Shapes** — «Фигуры», а конкретный набор шаблонов — **stencil**, по-русски обычно «набор фигур» или «трафарет». Рабочая область называется **drawing page** — «лист рисунка» или, в вашей терминологии, **canvas**.

| Элемент Visio | Аналог в нашей модели |
|---|---|
| Набор фигур / stencil | TBox: каталог классов и шаблонов |
| Master shape, например `Square` | Класс, например `Human` или `Automobile` |
| Перетаскивание фигуры на лист | Утверждение `(instance ... ...)` |
| Автоматически созданный экземпляр фигуры | Индивид с `id` |
| Имя экземпляра `Square.2` | `Alice01`, `AliceCar01` |
| Лист рисунка / canvas | ABox: область экземпляров |
| Окно Shape Data / свойства фигуры | `attribute`, `names`, `age`, `possesses` |
| Связь между фигурами | `possesses`, `part`, `located` и другие отношения |

Сценарий в Visio:

1. В панели **Shapes** есть мастер-фигура `Human`.
2. Вы перетаскиваете её на лист.
3. Visio создаёт не новый master, а **экземпляр master-фигуры** с уникальным именем, например `Human.1`.
4. Перетаскиваете ещё одну — появляется `Human.2`.
5. На листе теперь два конкретных экземпляра одного шаблона.

Это почти буквально соответствует:

```lisp
(instance Alice01 Human)
(instance Alice02 Human)
```

Здесь:

- `Human` — master shape в TBox;
- `Alice01`, `Alice02` — экземпляры на «листе» ABox;
- `01`, `02` — уникальные маркеры экземпляров;
- имя «Алиса» может быть одинаковым у обеих фигур, но их `id` различны.

## Уточнение аналогии

Небольшая поправка: в Visio имя вида `Square.2` обычно является **именем экземпляра фигуры на листе**, а не обязательно глобальным уникальным идентификатором во всей книге. В семантической базе важнее глобальная уникальность: `Alice01` должен однозначно указывать на одну запись в ABox.

Поэтому точнее так:

```text
Visio:  master Square → экземпляр Square.2 на листе
SUMO:   класс Human → индивид Alice01 в ABox
```

А если на листе уже есть `Alice01`, то второй экземпляр того же класса получит другой маркер:

```text
Alice01, Alice02, Alice03, ...
```

## Итоговый рассказ

Представьте TBox как панель **Shapes**: там лежат не конкретные люди, а шаблоны — `Human`, `Automobile`, `Red`. Когда вы «перетаскиваете» шаблон `Human` на лист ABox, система не копирует сам шаблон, а создаёт экземпляр с уникальной меткой:

```lisp
(instance Alice01 Human)
```

Потом в окне свойств этой фигуры можно вписать данные:

```lisp
(names "Алиса" Alice01)
(attribute Alice01 Female)
```

Затем вы перетаскиваете шаблон `Automobile` и получаете `AliceCar01`:

```lisp
(instance AliceCar01 Automobile)
(possesses Alice01 AliceCar01)
(attribute AliceCar01 Red)
```

На листе ABox появились два экземпляра — `Alice01` и `AliceCar01`, — а абстрактные значения `"Алиса"`, `Female` и `Red` остались в системе понятий и были привязаны к этим экземплярам как имя, атрибут пола и цвет. [arxiv](https://arxiv.org/html/1705.10217v3)
